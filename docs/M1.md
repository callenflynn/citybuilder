# M1 Design Note — First Playable

## Goal
A playable, deterministic toy city: move a smooth camera over streamed,
seeded terrain; place grid-snapped roads (node/segment graph with Bezier
segments + first-class lane data); generate lots along roads; place
procedural buildings (from code-generated placeholder textures) only on
valid road frontage; keep a separate pedestrian-path network type.

Acceptance:
- Smooth 60 FPS while moving through streamed terrain.
- Roads can be built; buildings only place on valid road frontage.
- Determinism test passes (same seed + same placement log -> identical state).

## Data structures

### Chunk (terrain)
```
Chunk:
  cx, cy: int            # chunk coordinates
  heightmap: float32[c, c]  # from worldgen.generate_chunk(cx, cy, seed)
  dirty: bool            # needs re-upload to GPU
```
A `ChunkManager` holds an LRU cache of chunks around the camera. Chunks are
generated deterministically from (cx, cy, seed); no edits yet (terraforming
is M1.5). Streaming: load chunks within a radius, unload outside.

### Road graph (nodes + segments)
```
Node:
  id: int
  pos: vec2 (x, z)       # snapped to road grid at placement time
Segment:
  id: int
  from_node, to_node: int
  curve: Bezier          # start=from.pos, end=to.pos, ctrl1, ctrl2
  lanes: LaneData        # first-class lane info
LaneData:
  lane_count: int        # e.g. 2
  direction: str         # "forward" | "backward" | "both"
  width: float           # per-lane width
  allowed_vehicle_types: set  # e.g. {"car", "pedestrian"}  (M3 flesh-out)
Bezier:
  p0, p1, p2, p3: vec2   # p0=from, p3=to, p1/p2 controls (straight = p1=p0, p2=p3)
```
Grid snap: `snap(v) = round(v / GRID_SIZE) * GRID_SIZE`. All node positions
are snapped at placement; the stored curve is built once from snapped nodes
(so grid, free-draw, and auto-curve share one representation — free-draw and
auto-curve are M1.5+/M2 concerns; M1 is grid-snapped straight segments with
optional Bezier handles defaulting to straight).

### Lots
```
Lot:
  id: int
  footprint: list[vec2]   # polygon adjacent to a road segment
  segment_id: int
  along_offset: float     # distance along segment where lot starts
  building: Building | None
```
Generated along each road segment at regular intervals (lot depth from road,
lot width along road). A lot is "buildable" if its footprint doesn't overlap
another lot.

### Building (procedural, placeholder textures)
```
BuildingDef (data file):
  footprint_rules, floor_count, roof_type,
  wall_texture, window_texture, roof_texture  # references; placeholders gen'd in code
Building (instance):
  def_key: str
  variant: int            # seeded pick
  position: vec2
  orientation: float
  mesh: GPU mesh (instanced)
```
Placeholder textures generated in code (checker, brick, window grid, asphalt)
and uploaded once. Building geometry: extrude footprint to height, tile
wall/window textures, cap with roof. Drawn instanced.

### Pedestrian paths (separate network)
```
PathNode: id, pos
PathSegment: id, from, to
```
Kept separate from the road graph; connects to roads at sidewalks/crossings
(later milestones). M1: the type exists and can hold nodes/segments, no
simulation interaction yet.

## Interfaces

- `worldgen.generate_chunk(cx, cy, seed, chunk_size) -> heightmap` (exists)
- `ChunkManager(camera, seed, chunk_size)`:
  - `update(camera_pos)` -> set of chunks to draw this frame
  - `chunk_at(cx, cy)` -> heightmap
- `RoadGraph()`:
  - `add_node(x, z) -> node_id` (snaps to grid)
  - `add_segment(n1, n2) -> segment_id` (builds straight Bezier + default lanes)
  - `nodes()`, `segments()` -> bulk arrays for instanced rendering
  - `segment_geometry(segment_id) -> sampled points along the curve`
- `LotGenerator(graph)`:
  - `generate() -> list[Lot]` (rebuild when graph changes)
- `ProceduralBuilding(def_key, rng, footprint) -> Building` (placeholder mesh)
- `Renderer` extensions (M1): draw terrain chunks (heightmap as mesh), road
  segments (instanced lines/ribbons), buildings (instanced meshes).

## Risks
- Determinism: node/segment IDs and iteration order must be stable (insertion
  order, sorted by ID) so the same placement log replays identically.
- Lane data must be on Segment from day 1 (rule 6) even though M3 consumes it.
- Chunk streaming must not hitch the 60 FPS render loop; generate chunk
  heightmaps on a background thread or cap chunks-per-frame.
- Building placement must validate road frontage (lot touches a segment) and
  reject overlaps.

## Tests (M1)
- road grid snap determinism
- lot generation produces non-overlapping lots along a segment
- building placement only on valid road frontage (reject off-road)
- replay test: seed + placement log -> identical state hash after N ticks
- headless benchmark: stream chunks + place roads/buildings, measure ms/frame
